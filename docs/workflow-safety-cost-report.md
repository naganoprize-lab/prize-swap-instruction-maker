# 実装・検証記録：原価再計算・詳細ドック・作業フロー

基点 `2273ca9`。作業ブランチ `feat/workflow-safety-cost-docking`。前段階の編集可能な指示書と番号付き地図を引き継ぎ、各機能を分けて実装した。顧客Excel・実際のマシン情報はリポジトリへ含めていない。

## 原因と変更

- 候補のチェック列はpressのみを消費しreleaseをQtへ渡していた。行選択と共通チェックを相互更新する処理もあった。press/releaseを対で処理し、チェック・行フォーカスを分離。ボタンなし移動でドラッグ状態を解除し、自動スクロールを停止。再表示時はスクロール・ソート・フォーカスを保持する。
- 原価は従来正式単価が先で、PO評価と原価率取得は別経路だった。`costing.cost_profile`へ統一し、同じ商品の保存済み確認値→安全な末尾候補→正式単価の順とした。末尾候補は推定の取得元と注意を表示し、Vol/型番/サイズ等の曖昧な数字は自動採用しない。
- 選択した単価×獲得個数÷売上から計算する原価率・総原価を、元のExcel原価率・総原価から分離した。PO実測値は変更しない。売上0、個数欠損、期間未確認、設置前を含む期間、商品相違、複数商品混在が判明している実績、重大な品質異常では再計算しない。
- `effective_stat`・PO評価・マシンレコード・KPI・レーダーが同じ値を使用する。確認原価の変更と目標設定の変更は、未保存編集を維持して即時再評価する。実数値一覧の総原価も同時更新する。
- 詳細ダイアログのUIを`MachineDetailPanel`へ分離し、売り場ページ内の`QMainWindow(Qt.Widget)`に`QDockWidget`を設置した。既存のView/Sceneを中央に保持する。右50%・左・独立・再ドッキング・幅変更、位置/サイズ/開閉の保存、画面外復帰に対応。既存のダイアログAPIは同じパネルの互換ラッパーとして維持している。
- 詳細表示は同じパネルを再利用する。未保存編集は保存/破棄/キャンセルで保護し、保存時は変更フィールドだけを最新マシンに適用する。複数選択を解除しない。短い高DPI画面でもドックの最小高さで保存ボタンが外へ押し出されないようにした。

## 実データ・画面・帳票

添付された景品運営分析表は304実績を認識した。自動判別経由と従来読込の全実績値・期間・抽出日時・ファイル識別情報が一致し、元ファイルは変更されないことを読み取りで確認した。

`workflow_visual_check.py`は300台の合成データで実ウィジェットを操作する。原価編集・レーダー・共通選択・Undo/Redo・左右/独立表示・候補ホバー/ホイール・数値理由・手動列対応・印刷前停止/続行・3書類PDF・直接印刷経路・プレビュー・保存復元を確認し、スクリーンショットとJSON報告を保存する。既存のfullscreen/workspace/analytics/instructions probesも保持する。

Windowsワークフローはソースの100/125/150%表示と、ポータブルEXEの150%表示で新しいprobeを実行する。従来の全画面200%、A4/A3、印刷・フォント・帳票基準PDFの検証も維持する。用紙が混在する作業セットはページごとの用紙設定を使用する。

## 保存・制約

- 既存の売り場JSONと一時保存JSONに追加項目を持たせ、旧形式は既定値で復元する。置換前バックアップ`.bak`と既存自動保存を維持する。
- `workflow_state`は監査履歴（最大5000件）、判定根拠（最大10000件）、読込プロファイル、実ファイル活動、作業セット設定を保持する。再起動後のUndo/Redoは復元せず、監査履歴と分離する。
- 原価候補は商品名だけで確実と証明できないため取得元を明示する。型番等が末尾の金額と同形の場合は担当者の確認が必要。元の実測値は別に保持する。
- Excelレイアウトの「現在の配置を保持」は既存の対応枠だけを更新する。新しい枠を取り込みたい場合は、内容を確認して配置読込を選ぶ。元Excelのマクロは実行しない。
- 物理プリンターで紙に出力する検証はこの実行環境では行わない。直接印刷ダイアログ後の共通描画経路をPDFプリンターへ流し、保存PDFと一致することを検証する。実際のプリンタードライバーによる異種用紙切替は別途現場確認が必要。


## 最終検証の経過

ローカルの全579件は成功（413.86秒）。この実行の直後に追加した商品相違・複数景品混在の保護と総原価の即時表示も、関連68件・25件の実行で成功した。

最初のWindows実行 #43 は200%の全画面詳細検証で停止した。従来のダイアログ向けの判定が、埋め込み後も内部編集ウィジェットをOSの作業領域と比較していた。ドックの実際のホスト領域と保存操作部品を検証する方式へ変更し、全画面の画面領域とタスクバー除外領域を分け、診断に各矩形を残す。640×360論理ピクセル（200%）の仮想画面でも保存ボタンまでホストに収まることを追加検証する。

さらに、実画面上のドック座標まで確認するテストで横方向のはみ出しを再現した。全画面中にresizeEventが凡例を再表示することと、選択ツールバーの最小幅が画面幅を超えて親レイアウトを広げることが原因だった。全画面中は凡例を復活させず、全画面・選択ツールバーを同じウィジェットのまま幅に応じて折り返す。ドックと保存ボタンだけでなく、全画面の操作ボタンの画面内配置も検証する。

Windows #44 は前段の帳票テストを通過し、全テストでQt PDFプレビューのファイルロックを検出した。QPdfDocumentがパスで開いた一時PDFを描画中に保持し、Windowsで用紙変更時の置換と終了時の削除が失敗していた。生成PDFを寿命管理したQBufferから読み込み、閉じる前にビュー・文書・バッファの順で参照を解除する方式へ変更した。プレビューを開いたまま元PDFを削除・再生成できるテストを追加し、地図・作業セット・実画面の関連14件と全画面/選択の関連46件が成功した。
