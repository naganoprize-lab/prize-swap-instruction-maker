# 追加改修の調査・段階計画

基点2273ca9、作業ブランチfeat/workflow-safety-cost-docking。既存の指示書・地図・番号・保存・自動最適化は引き継ぐ。

1. 候補一覧：チェック列のpressだけを消費してreleaseをQtに渡している。さらに選択変更→共通選択→一覧全選択再構築という循環があり、行フォーカスでもチェックが変化する。press/releaseを対で処理し、チェックと行フォーカスを分離、ドラッグ状態を終了時に解除、スクロール・ソートを更新時に保持する。
2. 原価：evaluate_poは正式単価を先に選び、未確認末尾候補を計算へ使わない。原価率はeffective_statがExcel値を返し、確認済み原価の更新から切り離されている。共通原価サービスで取得元・元の実測値・再計算値を分離し、手動→安全な末尾候補→正式単価の順に選ぶ。
3. 印刷前チェック：既存ProductとBoothの照合を使い、重大矛盾のみ停止。空欄指示は情報、位置不明・未割当・数量未定は警告として埋め込みパネルから対象へ移動する。
4. 操作履歴：既存の指示QUndoStackと売り場QUndoStackを利用し、監査記録は別に永続化。入力中のショートカットはテキスト編集を優先する。
5. ホーム：実数KPI、注意、最近の操作と目的別タイル。画像の数値はサンプルとして使わず実データを集計する。
6. 作業セット：既存指示書・地図と同じBooth番号からA4チェックリストを追加し、共通描画計画で任意の組合せを出力する。
7. 判定理由：既存ルールの結果・実数値・期間・ルール設定のスナップショットを保存し、埋め込み理由パネルで確認する。
8. Excel：既存インポーターを利用し、シートとヘッダーで種類を検出。列対応プレビュー・手動対応の保存・検証後反映を追加する。
9. 詳細ドッキング：既存詳細編集コンポーネントを再利用し、売り場ページにドック可能な領域を設ける。右50%・左・フローティング、状態保存と画面外復帰、切替時の未保存保護を実装する。
10. 各段階のテスト成功後に次へ進み、最後に全件・Windowsネイティブ・EXEを検証する。既存テストは維持する。
