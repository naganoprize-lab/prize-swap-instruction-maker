# 全台5段階評価・適正PO・ホーム統合計画

基点は検証済み2f9f89c。main 3880a54には直接変更せず feat/home-five-band-analysis で進める。

1. 既存の売上・平均・照合・JSONを再利用。売上を20/40/60/80百分位の5段階へ拡張し、同額・0・欠損・取得元別期間を維持する。固定境界と分位点を設定可能にする。
2. P/Oの原値と景品獲得数/プレイ回数を区別。Excelに定義がなければ未確認と表示し、明示的な確認または実測個数・回数だけを評価に利用する。原価候補の取得元・信頼度・相違、実測単価と仮料金、差ptを追加する。
3. レーダー実数値表示を維持し、単独・全台同額の売上は未評価。PO評価方式・日数基準・原価許容範囲を設定化する。欠損は—、内部数値は非表示。
4. 共通の区分を画面・分布・PDFで使い、PO5区分・原価5区分・日数10日境界を統一。比較分析/詳細データへの導線、タイル順序・拡大・短縮名を整える。
5. 候補ページを再利用し、同一期間長・同一商品/方法の実在履歴で売上金額の推移を保持。指示書への重複登録を確認する。
6. ホームを機能タイルと4KPI中心に刷新。既存ページを再利用し、入荷予定は既存商品データと登録日を使う実用的な一覧とする。入荷日が存在しなければ捏造しない。レイアウトの座標・サイズ・ズームは触らない。
7. 段階ごとの集中テスト、全pytest、実データの整合性、ライト/ダークと高DPI実描画、Windows EXEとスモーク・ZIPまで検証する。旧テストを削除・無効化せず、指定された新仕様の期待値を更新する。

原ExcelのP/O定義は列名だけで確定しない。原値と計算済み指標の区別を優先する。実機プリンターは未確認として報告する。

## 追加依頼：選択状態と候補の指示書への一括追加

- 永続的な `Machine.uid` を共有選択キーとして使用。画面の座標、色、サイズとは別に保持する。
- 通常・範囲・個別、Ctrlクリック、Shift範囲追加、全選択／解除を既存のQGraphicsViewに統合する。
- 売上分析の「全台／レイアウト選択中」を追加。分布の集計対象だけを絞り、売上の比較母集団は全台を維持する。
- 候補の単体／判定区分一括追加は、確認後に既存Productへ下書きを作成。新商品名・数量・確定入替日は補完せず、現行情報はcandidate_assignmentへ分離する。
- 商品名未設定の下書きは初期出力対象外。内部UIDで追加済みを管理し、旧形式の機械番号も正規化して重複を防ぐ。
- ユーザー確認により元の景品運営分析表のP/O率は「景品獲得数÷プレイ回数」と確定。元表の読込ではその定義を設定する。原値と定義の個別変更機構は維持する。
