# 日別参照・期間集計・タイムラプス 実装計画

基点92e92b6。Windows/PySide6のみを対象とする。既存の単一Excel読込・帳票本体・機械照合・選択・テーマを維持する。

1. 既存サービスを再利用する日別ライブラリをSQLiteの別キャッシュとして新設。ファイル・改訂・日付判定・原始実績・日別レイアウト・参考表・ユーザー確認を保存する。フォルダー設定は既存JSONへ追加し、古い保存データは初期値で移行する。
2. フォルダー走査はバックグラウンド。サイズ/mtime/ハッシュで未変更ファイルを再解析しない。~$を除外し、破損時は正常データを維持。マクロは実行しない。
3. 日付はExcelの明示期間を優先する。逆転/不完全な期間をファイル名だけで上書きしない。同日重複、異日同一売上、累計の重複・部分利用を確認対象にする。
4. 集計は非重複の確定日/確定期間のみ。売上・原価・払出の合計、原価率とPO率の分子/分母、既存基準によるアベ比を共通サービスで算出。不明日を0にせず、取得/未取得・部分集計を明記する。
5. 現在の編集マスターと履歴の表示用モデルを分離する。同じUIDと現在の物理座標を使い、日付変更で指示書・手動修正・保存内容を変更しない。履歴詳細は参照用とし、編集は現在データで行う。
6. ホーム/レイアウト/分析/候補に同期する期間コントロール。レイアウト内に折りたたみタイムラインを追加。日別/月別、再生/停止/速度/ループ/欠損日、変化枠と前後差分を実装する。QGraphicsItemとズーム/スクロール/複数選択/詳細ドックを再利用する。
7. 時系列グラフ、候補の補助推移、期間の取得元を表示する。選択台分析と全台の順位基準を保持する。
8. 独立した人工データで各段階を検証し、全既存603件・追加テスト・実画面・既存帳票の変更前後比較・Windowsソース/ポータブルEXEを検証する。

## 実装経過

- 日付/重複/非重複集計の基盤：18件、共通期間計算を含む関連55件を通過。
- フォルダー設定・同期期間UI・バックグラウンド集計・埋め込み再生：詳細ドックを含む34件を通過。初期表示用データと現在の編集マスターを分離し、現在の指示書/地図/印刷は物理マスターを参照する。
- 日別補正は日付/ファイル改訂別のSQLite設定に保存。Undo/Redoは既存の履歴スタックを使用。期間合計は参照専用。
- SQLiteスキーマ2では軽量メタデータ索引を追加。旧スキーマ1を移行し、日付一覧の更新で全実績JSONを再解析しない。フレームLRU12件、次フレームの先読み、キャンセルを実装。
- 時系列7タイル・前回取得日/同条件の補助推移・選択台連携・列順/シート名の自動判別：追加30件を通過。
- 300ブース生成データの画面プローブを追加。全フィルター、明暗テーマ、マスター/座標/選択の保持、欠損日、選択24台、原本非変更を検証。Windowsソース100/125/150%とEXE150%に同じ検証を追加。
